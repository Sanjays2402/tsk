## Why these / quality notes

- This is the documented T3 batch from STATE-web.md — no padding, no splitting.
- F12 is the ONLY backend change: a new read-only `GET /api/parse-date?q=` over
  internal/dateparse. It SOFT-fails (200 + `ok:false`) on unparseable input so
  the live picker doesn't 400-spam on every keystroke; missing `?q` is a hard
  400. DST-safe relative-day rounding shared with the web formatDue.
- Every slice carries a pure, dependency-free logic module unit-tested under
  Node's native TS runner: `filter.ts` (16), `duepicker.ts` (13), `stats.ts`
  (10), `theme.ts` (8), `router.ts` (11) = 58 new frontend tests (106 total).
  Plus 4 new Go tests on internal/serve for the parse-date endpoint.
- F11 keeps the store untouched: filtering is purely client-side over the list
  the API already returns. Facets are OR-within / AND-across; fuzzy search is a
  whitespace-tokenized subsequence match over title+tags.
- F13 stats re-fetch only after store-changing mutations (toggle/delete/due),
  NOT on filter keystrokes, since stats describe the whole store.
- F14 refactored tokens.css to key the palette off `<html data-theme>` so an
  explicit dark choice can beat a light OS preference; "auto" still follows the
  media query. Applied before first paint to avoid a flash.
- F15 composes cleanly with F11: a tag route pre-narrows the pool, the filter
  still applies on top. Row tag pills became buttons that navigate; the
