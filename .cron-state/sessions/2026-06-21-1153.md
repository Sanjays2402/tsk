## Process notes

- Tick #14's `writeWeeklyArchive` was refactored into a generic
  `writeBucketedArchive(path, arch, batch, bucketFn)` so that
  weekly and monthly share the same buffer/sort/render logic with
  only the per-task (key, sortKey) function differing. Kept the
  policy identical: never re-bucket existing content; "undated"
  always to the tail; per-bucket id-ascending order; .bak
  snapshot via store.AtomicWriteFile.

- For `tsk topo --since --reverse`, the FIRST implementation
  sliced by linear position in the topo sequence — caught by a
  cycle-visibility test that exposed the semantic bug. Kahn's
  algorithm sorts the ready set by priority, so isolated tasks
  drain in lock-step with real prereqs; positional slicing pulls
  in unrelated work. Rewrote `sliceTopoBefore` to compute the
  prereq set via reverse BFS through DependsOn edges, then
  intersect with the original topological order so emission stays
  dependency-respecting. This is what the user actually means by
  "what gates this milestone?" — and the existing unit test had
  to be updated to set explicit DependsOn slices on the synthetic
  topoTask values (folded back into the topo commit via fixup +
  autosquash so per-feature one-commit revertibility stayed
  intact).

- For `tsk export --graph-dot`, the implementation routes through
  the existing `emitGraph(w, s, edges, "dot", reachable)` helper
  in graph.go so the "no dependencies" / "no dependencies
  reachable from #N" empty-state messages are byte-for-byte
  identical to `tsk graph`. A regression test asserts the two
  surfaces stay in lockstep. Also added `--reachable` /
  `--open` to the export command and rejected them up-front with
  a clear error when paired with a non-graph format (silently
  ignoring would be confusing).

- For `tsk lint --autofix-all`, the design choice was to credit
  ONE repair for the entire round-trippable bucket (a single save
  fixes all the bullet/meta/notes findings) and ONE repair per
  semantic backfill (each missing-created task is a distinct
  fix). Idempotency is automatic: re-running on a clean file
  short-circuits at the "findings == 0" check and emits "all
  checks passed" without writing.

- Used time.Now() for the backfill rather than file mtime: since
  the very next thing we do is save (which overwrites mtime to
  now()), they converge on the same outcome; now() is the more
  honest "the stamp happened JUST NOW" choice. Documented these
  as best-effort placeholders, not real creation times.
