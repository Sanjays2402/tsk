## Why these 5 fit together

These weren't five random features — they form a workflow:

1. **discover** what's stuck (`blocked`)
2. **visualize** the graph (`graph`)
3. **drill** into one chain (`depend --tree`)
4. **plan** around blockers (`--respect-deps`)
5. **clean up** duplicates via merge w/ back-ref rewrite (`merge`)

Tick #9 added the dep storage + done-blocking enforcement. Tick #10 made it
*usable* with proper discovery / inspection / planning / cleanup tooling.

## Non-obvious decisions

- **`blocked` as top-level, not alias.** A cobra alias `tsk depend blocked`
  would bury it. Top-level shows in `tsk --help`, gets its own completion entry.
- **Tree cycle protection.** Writer rejects 2-cycles only (tick #9 design).
  Tree walker uses visit-set guarded DFS so a hand-edited 3+ node cycle
  renders "(cycle)" instead of looping forever.
- **Graph arrow convention** matches `depend --on` English ("A -> B = A depends
  on B"). Matters because users context-switch between `--tree` and `graph`.
- **`--respect-deps` defaults OFF.** Existing scripts piping `tsk next`
  shouldn't break. When it IS set and EVERYTHING is blocked, we fall back to
  "best blocked + (blocked by #X) annotation" instead of lying "all caught up".
- **`merge` back-ref dedupe.** Third task that depended on BOTH survivor and
  victim → after rewrite, survivor appears exactly once (not twice). Tested
  directly.
- **`merge` mutual-dep refusal.** Clear the relationship explicitly first.
  Implicit handling would hide the relationship in unexpected ways.
