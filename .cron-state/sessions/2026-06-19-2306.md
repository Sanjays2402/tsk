## Notable design choices worth remembering

- **`top` tie-break matches `next` exactly.** Priority desc → dated-
  first → earliest-due → lower-id. A regression test
  (`TestTopOrderingMatchesNext`) verifies `top[0]` and `tsk next`
  surface the same task. If `next`'s ordering ever changes, both
  must change together.
- **`today`/`overdue` route through applyFilters.** They preset the
  filter bit and let the existing `ls` machinery do everything else.
  Single source of truth for filter semantics → adding `tsk tomorrow`
  later is a one-liner via dueWindowConfig.
- **`tags` JSON emits [] not null when empty.** Cheap insurance for
  jq pipelines (`.[0].tag` on `null` would error out). Documented
  via TestTagsJSONEmitsEmptyArrayNotNull.
- **`log` strict time-ordering.** Tasks marked done but missing a
  Completed timestamp (old files hand-edited from `[ ]` to `[x]`)
  are EXCLUDED from rows entirely — log is a journal, not a catalog.
  A footer line counts the skipped ones so users can audit. JSON
  mode stays silent (contract is just the task array).
- **`grep` field annotation precedence: title > tag > notes.** Same
  task matching in multiple fields gets the most informative label.
  Locked by TestGrepTitleFieldPrecedenceOverTag so a future refactor
  can't accidentally reorder.
- **`grep` -v NOT used as --invert short flag.** `-v` would collide
  visually with `tsk version` and confuse muscle memory. Documented
  in the command's Long help.
- **All output modes mutually exclusive in `grep`.** --files-only +
  --count, --files-only + --json, --count + --json all rejected
  upfront with usage errors. No surprising output combinations.
